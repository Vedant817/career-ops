# Career-Ops apply-all launchers

One "apply everything" one-shot workflow (`ONE_SHOT_APPLY_ALL_GITHUB_PLUGIN.md`
at the repo root), five CLI-specific launcher scripts, and one entry point that
runs any of them. Every launcher does the same four things before handing off
to its CLI:

1. Verify the CLI is installed.
2. Register the Keychain-aware Playwright MCP launcher (`playwright-mcp-keychain.sh`)
   under that CLI's own MCP mechanism, so Workday password autofill works the
   same way it does for Codex.
3. Bootstrap `portals.yml` / `npm ci` / `node doctor.mjs` if needed.
4. Launch the CLI interactively (not headless/print mode -- the workflow pauses
   mid-run to ask for OTPs and other decisions only Vedant can make) with full
   tool-approval bypassed and the one-shot prompt as the initial message.

None of the scripts verify the GitHub connection themselves -- that check is
part of the shared prompt's "Mandatory integration rule" and happens inside
the agent session itself, for every CLI. If the connected GitHub account isn't
`Vedant817`, the agent stops before scanning jobs and tells you what to fix.

## Usage

```bash
automation/apply-all/run-all.sh              # interactive menu of installed CLIs
automation/apply-all/run-all.sh claude        # run one directly
automation/apply-all/run-all.sh all           # run every installed CLI, one at a time
```

Or run a single CLI's script directly: `automation/apply-all/codex.sh`,
`claude.sh`, `opencode.sh`, `grok.sh`, `cursor.sh`.

`run-all.sh all` runs sequentially, never in parallel -- the workflow shares
`data/application-review-queue.md` and `output/applications/` across runs and
is explicitly designed to detect and resume that state rather than repeat
completed work, so running each CLI one after another is safe and even useful
(a role blocked in one CLI's browser session can be picked up cleanly by the
next).

## Per-CLI notes

| CLI | Playwright MCP registration | Full-autonomy flags |
| --- | --- | --- |
| Codex | `codex mcp add playwright -- <launcher>` (global) | `--sandbox danger-full-access --ask-for-approval never` |
| Claude Code | `claude mcp add playwright -- <launcher>` (project-local scope) | `--dangerously-skip-permissions` |
| OpenCode | `mcp.playwright` entry merged into `opencode.json` (project config; no CLI flag exists for a local/stdio server) | `--auto` |
| Grok Build CLI | `grok mcp add --scope project playwright -- <launcher>` (`./.grok/config.toml`) | `--permission-mode bypassPermissions` |
| Cursor | `mcpServers.playwright` entry merged into `.cursor/mcp.json`, then `cursor-agent mcp enable playwright` (no `mcp add` subcommand exists) | `--force --approve-mcps --sandbox disabled` |

`opencode.json`, `.cursor/mcp.json`, and `.grok/config.toml` are generated by
these scripts and gitignored -- they embed this checkout's absolute path, so
they're machine-local and regenerate on demand rather than being committed.

Every full-autonomy flag above is that CLI's own documented "skip permission
prompts" mechanism, chosen to match Codex's existing `--ask-for-approval
never` posture. Several of these CLIs' own `--help` text notes this is
recommended only in environments you trust -- review before your first run.

GitHub integration is CLI-specific and each script prints one-time setup
guidance for it; only what's already confirmed to exist is stated as fact,
the rest is described as "set this up, then rerun."
